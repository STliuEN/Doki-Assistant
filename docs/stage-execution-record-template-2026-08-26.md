# 分阶段执行记录模板

用途：架构重构每个阶段的唯一执行记录格式。模板本身不代表阶段已开始或已完成；状态必须与[架构重写计划](./architecture_rewrite_plan.md)一致。

## 状态枚举

只能使用以下六种状态：

`草案` -> `待你确认` -> `实施中` -> `待验证` -> `已关闭`

出现外部依赖、证据或决策无法满足时使用 `阻塞`；解除阻塞后回到 `待你确认`，不能直接跳到 `实施中`或`已关闭`。

## `plan.md` 模板

```markdown
# <阶段编号> <阶段名称>

日期：YYYY-MM-DD
状态：草案 | 待你确认 | 实施中 | 待验证 | 已关闭 | 阻塞
负责人：<owner>
审阅/批准人：<approver>
用户确认：<日期、确认范围；未确认写 pending>

## 目标

- 

## 非目标

- 

## 依赖与入口条件

- 上一阶段关闭证据：
- 环境/版本/拓扑：
- 备份、停写和迁移开关：

## 任务清单

- [ ] 任务、代码/文档路径、预期产物、完成判据
- [ ] 

## 风险与保护

- 不得修改/删除的对象：
- fail-closed 条件：
- 受影响的提前切片及返工范围：

## 退出条件

- [ ] 功能/结构产物已生成
- [ ] 数据行数、digest、generation 或审计对账通过
- [ ] 负向/恢复/回滚测试通过
- [ ] 真实依赖与替身边界已注明
- [ ] 用户确认关闭

## 回滚方案

命令、快照/备份、停写窗口、恢复后校验、负责人：

## 未完成与阻塞

- 项目：状态、原因、解除条件、下一步
```

## `change-log.md` 模板

```markdown
# <阶段编号> 变更日志

状态：<与 plan.md 相同>

| 时间 | commit/文件/schema | 变更 | 原因 | 影响 | 回滚点 | 负责人 | 证据 |
|---|---|---|---|---|---|---|---|
| YYYY-MM-DD |  |  |  |  |  |  |  |

## 明确未做

- 未执行的迁移、删除、功能或测试必须列出，不能留空造成完成误读。
```

## `test-record.md` 模板

证据状态只使用 `verified-local`、`verified-live`、`blocked`、`not-run`。`fixture`、`mock`、`historical` 是证据类型，`passed`、`failed`、`invalid`、`limitation` 写在“结果/处置”，不能再扩展成第二套状态枚举。

```markdown
# <阶段编号> 测试与迁移证据

状态：<与 plan.md 相同>

## 环境限制

- 平台/解释器/运行时版本：
- MySQL/Chroma/模型拓扑：真实 | fixture | mock
- 未连接或未修改的数据：

## 证据表

| ID | 环境/版本 | 拓扑 | 证据类型 | 命令 | 阈值 | 实际结果 | 结果/处置 | 日志/文件 | owner | approver | 状态 |
|---|---|---|---|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  |  |  |  | verified-local / verified-live / blocked / not-run |

## 数据对账

- 源表/目标表行数：
- source/content digest：
- generation/active pointer：
- 审计事件和 correlation ID：
- 差异及处理：

## 负向与恢复覆盖

- 越权、过期、撤销、重放、digest 漂移：
- 进程 kill/restart、超时、取消、重复、乱序：
- Chroma 故障、重建、旧 generation 清理：
- 备份、恢复、restore-forward、回滚：

## 不能证明的内容

明确写出 fixture、mock、单平台或未连接真实依赖不能证明什么。
```

## 关闭规则

1. 阶段完成实现后只能标 `待验证`，同时提交三份记录和所有证据路径。
2. 真实依赖缺失、阈值未达、审计字段缺失或回滚未演练时标 `阻塞`，不以绿色单元测试替代。
3. 用户确认关闭后才标 `已关闭`，并把下一阶段改为 `待你确认`。
4. 本地 debug/import/export/rollback 必须记录为显式操作，不能伪装成业务自动恢复。
