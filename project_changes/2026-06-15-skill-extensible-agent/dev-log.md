# 开发日志

## 项目方向

当前项目已经具备：

- 多模型接入
- AI 对话
- 实时翻译
- 笔记系统
- RAG 知识库

下一阶段希望把它升级为一个更接近 Codex 风格的可扩展 Agent 系统，支持：

- 多功能 skills
- 外部工具接入
- 用户自定义能力
- 模型、技能、工具的组合切换

## 当前问题

现在的 Agent 工具链是固定写死的，主要问题有：

- 工具列表集中在代码里
- prompt 只能靠固定配置切换
- 不方便按场景加载不同能力
- 外部工具接入成本高
- 用户无法自己定义技能包

## 目标

把系统拆成三层：

1. `Prompt Composer`
   - 组合主 prompt、AI 模式 prompt、技能 prompt

2. `Skill Registry`
   - 管理技能的描述、规则、可见性、可绑定工具

3. `Tool Registry`
   - 管理内置工具、HTTP 工具、外部工具

## 预期能力

- 用户可以选择技能
- Agent 可以自动选择适合的技能
- 技能可以绑定已有工具
- 后续可以接入外部 API 工具
- 再往后可以接 MCP / 浏览器 / 文件系统类工具

## 开发顺序

1. 先做静态技能注册
2. 再做 prompt 组合器
3. 再改造 Agent 的工具加载逻辑
4. 再接前端技能选择
5. 再支持用户自定义技能
6. 再支持外部 HTTP 工具
7. 最后再考虑 MCP 类型工具

## 风险点

- 安全：外部工具和用户自定义工具必须做权限控制
- 稳定性：工具调用要有超时和失败兜底
- 可维护性：技能配置不能继续堆在代码里
- 可解释性：需要保留调用日志，便于排查

## 备注

这份日志记录的是下一阶段的开发方向，不是当前已经完成的代码变更。
